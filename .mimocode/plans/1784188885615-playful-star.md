# SafariLink HR — Announcement & Department Features Plan

## Overview

Four feature areas:
1. Clickable announcement cards that open full-view with images
2. More announcement size variety (hero-sized options)
3. User-department assignment system (multi-department, admin/user management)
4. Webhook toggle for announcements/banners → n8n → WhatsApp

---

## Feature 1: Clickable Announcement Full-View Modal

**Problem**: Long announcements get truncated (`line-clamp-3`) and images are clipped to `h-28`/`h-48`. Users can't see full content or images.

**Solution**: Click any announcement card → opens a responsive modal showing the complete announcement.

### Files to modify:
- `src/components/BulletinBoard.tsx` — Add click handler to `BentoCard`, add `AnnouncementDetailModal` component

### Implementation:
- Add `selectedAnnouncement` state to `BulletinBoard`
- Make `BentoCard` clickable (except admin edit/delete buttons which stop propagation)
- New `AnnouncementDetailModal` component:
  - Full-width image at top (no fixed height, natural aspect ratio with max-height cap)
  - Scrollable content area for long text
  - Metadata footer (department(s), author, date, expiry)
  - **Mobile**: Full-screen overlay (`fixed inset-0 rounded-none`)
  - **Desktop**: Centered card (`max-w-2xl mx-auto`)
  - Close via X button, clicking backdrop, or Escape key
  - Admin sees edit button in modal header

## Feature 2: More Announcement Sizes

**Current sizes**: small (1x1), medium (1x1), wide (2x1), tall (1x2), large (2x2)

**Add new sizes**:
- `hero` — Full-width row (`sm:col-span-3`), taller image (`h-40`)
- `xlarge` — 3 columns x 2 rows (`sm:col-span-3 sm:row-span-2`), largest possible

### Files to modify:
- `src/types.ts` — Update `Announcement.gridSize` union type
- `src/components/BulletinBoard.tsx` — Update `GRID_SIZE_CLASSES`, update editor dropdown, adjust image heights per size

### Grid size class mapping:
```
small:  "" (1x1)
medium: "" (1x1)
wide:   "sm:col-span-2" (2x1)
tall:   "sm:row-span-2" (1x2)
large:  "sm:col-span-2 sm:row-span-2" (2x2)
xlarge: "sm:col-span-3 sm:row-span-2" (3x2)
hero:   "sm:col-span-3" (3x1, full row)
```

## Feature 3: User Department Assignment

**Problem**: Departments exist but users aren't assigned to them. No way to scope notifications or announcements per user-department.

**Key decisions**: 
- Announcements can target **multiple departments** (not just one)
- Users see announcements matching ANY of their departments + untagged announcements (global)

### Database changes (`src/db.ts`):
- New table: `user_departments` (user_id, department_id, PRIMARY KEY(user_id, department_id))
- New table: `announcement_departments` (announcement_id, department_id) — replaces single `department_id` column on announcements
- New table: `department_webhooks` (department_id PRIMARY KEY, webhook_url TEXT)
- Migration: auto-create "general" department if it doesn't exist
- Migration: assign all existing users to "general" if they have no department
- Migration: migrate existing `announcements.department_id` values into `announcement_departments` rows, then drop old column

### New API endpoints (`src/index.ts`):
- `GET /api/users/:id/departments` — List user's departments
- `POST /api/users/:id/departments` — Add department to user (admin)
- `DELETE /api/users/:id/departments/:deptId` — Remove department from user (admin)
- `GET /api/user/departments` — Current user's own departments (self)
- `POST /api/user/departments` — Current user adds a department to self
- `DELETE /api/user/departments/:deptId` — Current user removes a department from self
- `GET /api/departments/:id/webhook` — Get webhook URL for department
- `PUT /api/departments/:id/webhook` — Set webhook URL for department (admin)

### Announcement multi-department targeting:
- `POST /api/announcements` — Accept `departmentIds: string[]` array (empty = global)
- `PUT /api/announcements/:id` — Accept `departmentIds: string[]` to update targets
- `GET /api/announcements` — Filter: return announcements where at least one target dept matches user's departments, OR announcements with no target (global)

### Frontend changes:
- `src/api.ts` — Add API functions for user-departments and webhooks
- `src/types.ts` — Add `UserDepartment` type, update `Department` with optional `webhookUrl`, update `Announcement` to use `departmentIds: string[]`
- `src/components/BulletinBoard.tsx` — Announcement editor shows **multi-select department checkboxes** instead of single dropdown
- `src/components/UserSettings.tsx` — Add "My Departments" tab where users can add/remove themselves from available departments. Keep existing admin tabs (Users, Departments, Theme).
- `src/components/AdminDashboard.tsx` or inline in UserSettings users tab — Admin can manage which departments each user belongs to (add/remove chips)
- `src/components/AuthModal.tsx` — On registration, auto-assign "general" department

### Notification filtering:
- `GET /api/announcements` — Filter by user's departments: show announcements where at least one target dept matches one of user's depts, OR announcements with no target (global)
- `GET /api/banners` — Same filtering logic

## Feature 3.5: Image Upload (not just URL)

**Problem**: Currently only image URL input is available. Users need to upload images directly.

**Solution**: Add file upload endpoint that saves images to disk and returns a URL.

### Backend (`src/index.ts`):
- New endpoint: `POST /api/upload` — Accepts `multipart/form-data`, saves file to `data/uploads/` directory, returns `{ url: "/uploads/filename.ext" }`
- New static route: `GET /uploads/*` — Serves files from `data/uploads/` directory
- File validation: limit to images only (jpg, png, gif, webp), max 5MB
- File naming: use UUID prefix to avoid collisions

### Frontend (`src/components/BulletinBoard.tsx`):
- In `AnnouncementEditorModal`: replace single URL input with a tab UI — "Upload" tab (file picker + drag-and-drop) and "URL" tab (paste link)
- In `BannerEditorModal`: same dual-input approach for background image
- Upload preview: show uploaded image immediately after upload
- Same approach in `AnnouncementDetailModal` image display — works with both uploaded paths and external URLs

### Files to modify:
- `src/index.ts` — Add upload endpoint and static file serving
- `src/components/BulletinBoard.tsx` — Add upload UI to both editor modals

## Feature 4: Webhook Toggle for Announcements & Banners

**Problem**: No way to push announcements/banners to external systems (n8n → WhatsApp via Twilio).

### Database changes (`src/db.ts`):
- New column: `announcements.send_to_webhook INTEGER DEFAULT 0`
- New column: `banners.send_to_webhook INTEGER DEFAULT 0`
- New table: `department_webhooks` (already in Feature 3)
  - `department_id TEXT PRIMARY KEY REFERENCES departments(id)`
  - `webhook_url TEXT`

### Webhook payload (full content + image):
```json
{
  "type": "announcement" | "banner",
  "title": "...",
  "content": "...",
  "image_url": "...",
  "emoji": "...",
  "departments": [{ "id": "...", "name": "..." }],
  "priority": "normal|high|urgent",
  "author": "...",
  "created_at": "..."
}
```

### Implementation:
- `src/db.ts` — Migrations for new columns and table
- `src/index.ts` — When creating/updating announcements or banners with `send_to_webhook=true`, POST to the department's webhook URL
- `src/components/BulletinBoard.tsx` — Add "Send to WhatsApp" toggle in `AnnouncementEditorModal` and `BannerEditorModal` (admin only, only visible when a department is selected)
- `src/components/DepartmentManager.tsx` — Add webhook URL input field in department editor
